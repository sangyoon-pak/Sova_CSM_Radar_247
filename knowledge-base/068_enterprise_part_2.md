# Managing Segments

The **Segments** page displays all the segments in your project. From here, you can view segment details and manage your segments.

  * View segment details
  * Delete segments
  * Duplicate segments
  * Edit segments
  * Export segments to CSV

![](https://files.readme.io/d92c6f52f254f6539c98e93d09f830ae6fd5c0386ded38462002fe0a1520a4cb-segment-list-page.png)

View segment details

  * Click a segment's name to view its details.
  * Customize segment list columns to ensure the segment list only displays the most relevant information.
  * Search and filter segments to find segments quickly.

Customize segment list columns

Click ![](https://files.readme.io/5d63d29988787f1743d5e322a2d0e16839b6838113f1cc4fba1bdb393a902ed0-edit-column-icon.png) to add, remove, and reorder the columns displayed in the segment list.

---|---  
Add columns| Under **Add / Remove columns** , check the columns to display.  
Remove columns| • Under **Add / Remove columns** , uncheck the columns to hide.  
• Under **Selected columns** , click **X** to hide the column.  
Reorder columns| Under **Selected columns** , drag each column to your preferred position.

Search and filter segments

Use the filter dropdown menus to further filter segment list results by type, tag, and source.

## 

Export segments to CSV

Segment reports are CSV files containing user attributes, device attributes, and channel reachability for users in a segment.

  1. Click ![](https://files.readme.io/1e1263152ae6c7f19c05af715e10d3dd663439ce5ccb78e4f746c504c3df5cf7-more-options-icon.png) and select **Export to CSV**. 



![](https://files.readme.io/d42dde30c0febee40de9b5b85166ef47ded4fe404fde4429799bc88a38588665-segment-export-to-csv.png)

  2. Select user attributes and device attributes to include in the report.
  3. If you're only exporting user attributes, set the **Data scope** option to control how much historical data to include.



Data scope| Description  
---|---  
**Current snapshot**|  Exports the current (latest) user attribute values.  
**Full history**|  Exports all historical user attribute values.  
  
![](https://files.readme.io/a468652d1863d312b3f86550d3ddf406a234410542152eed250d81daeb500f0e-segment-export-to-csv-data-scope.png)

  4. Click **Preview report** to see how the report looks.

![](https://files.readme.io/58e9ccac88d278801b751e5a7449d1794f467064db40b010b2c64f4a25541903-segment-export-csv-preview.png)

  5. After previewing the report, click **Export** to generate the report. When the report is ready, you'll receive an email containing a download link.

# Split Node

There are three types of nodes that can split users into different paths in the journey.

  * **Check condition**: Split users based on their attributes and events.
  * **Check reachability** (Only available for BotBonnie channels): Split users based on the channels you can reach them with.
  * **Experiment**: Conduct an A/B test to determine which path is most effective.

![](https://files.readme.io/6632dd411588f46e5bcc7de35cb2a244ea99d4551512a302a6867720ad9e5b37-split-node-types.png)

* * *

## 

Check condition

The **Check condition** node can be used to split users into different paths based on their attributes and events.

![](https://files.readme.io/b4a394fff7a6e817d3440890d282b684ff9760502c6769cb6918fd7d20a851ed-check-condition-node.png)

  1. Enter a name, and under **Condition type** , select how users should be split.



Condition type| Description| Example use case  
---|---|---  
**Based on past event or attribute**|  Split users into different paths based on existing user attributes or past events.Note that recent events occurring within the past hour may not be detected.| • Split users into different paths based on their location.  
• Split users into different paths based on which page they viewed in last seven days.  
**Wait for future event**|  Split users into different paths based on future events. Set a wait time, then send users to the highest-priority path they satisfied conditions for.Note: The `is not` operator still evaluates to `true` if the parameter doesn't exist.| • Split users into path 1 when purchase a product and path 2 when they add a product to their cart.• Split users into different paths based on key events they complete in the next three days, such as adding a product to their cart or viewing a specific page.  
  
  2. Under **Wait behavior** , choose when to send users down the split path.



Wait behavior| Description  
---|---  
**Trigger immediately**|  As soon as a user satisfies the condition for any path, immediately send the user down that path.  
**Trigger highest-priority path after waiting period**|  Wait for a set period of time before checking user events. After the waiting period, check which paths the user satisfied conditions for, then send the user down the highest-priority path they satisfied conditions for.![](https://files.readme.io/9dbc4b33e40e9ed95ab5368092cb06269bc073de1278d768724fe5394d2e65c6-check-condition-waiting-period.png)

> 📘Note that in journey maps that are already running, modifying the event or event parameters in path conditions will clear records of users who satisfied path conditions. You can change the event count without clearing existing records.  
  
  4. Add different paths to split users into. If a user satisfies conditions for multiple paths, they'll enter the highest-priority one. Paths are prioritized in descending order, that is, **Path 01** is higher priority than **Path 02**. Use the arrows to change a path's priority.

![](https://files.readme.io/8aa4295fc515a41ebb11d2b1c47de9c85b8bf633b58596fc4d5f3472082ddae8-check-condition-path-priority.png)

> 📘
> 
> ### 
> 
> No path matched
> 
> If users don't meet any of the path conditions you specified, they'll enter the **No path matched** path.
> 
> ![](https://files.readme.io/7d5b23e1788079c1b5d84dc293a45dcd4c5d870b91e37f4990b70ba114f69c02-check-condition-no-path-matched.png)

* * *

## 

Check reachability

You can split users based on their reachability for the following channels:

  * LINE
  * Facebook Messenger
  * WebChat
  * WhatsApp



Select the channel next to **Check if the users are reachable on** and select the LINE Official Account. If needed, click **Add Channel** to add more paths for other channels.

![](https://files.readme.io/20b8779-reachable.png)   


* * *

## 

Experiment

Conduct A/B tests by randomly splitting users into different paths, allowing you to identify the most effective journey paths.

  1. Enter a node name.
  2. (Optional) Check **Enable control path** to create a control group. Users in the control group will be immediately be redirected to the end of the journey.
  3. Click **\+ Add test path** to add alternate journey paths. You can add up to five paths.
  4. You can name each path and set the traffic allocation by entering the percentage of users that should be sent to each one. Alternatively, click **Divide equally** to balance traffic equally between all paths, including the control group. The total percentage must add up to 100%.
  5. (Optional) If you'd like users who have completed or exited the journey and are re-entering to follow the same path they previously went on, check **Keep re-entering users on their original path**.

![](https://files.readme.io/dcd7034efab18fd0e426c0d08a4f1f6c23a8ff6b501f27862ff34978c1078af2-experiment-node.png)

# Test and Publish the Journey

## 

Test the journey

After you've finished creating your journey, you can test the journey to visualize how a user traverses the journey before publishing it. From the top bar, click **Test journey**.

![](https://files.readme.io/6354f0a-Screen_Shot_2024-03-22_at_10.52.10_AM.png)

To add a test user, click **Select user** and search for the test user. Next, select a user, and click **Select**.

  * Search by entering the complete email, phone number, or `user_id`. The search results only include users who exactly match the data you entered. Searches are case-sensitive.
  * You can only add one test user.

![](https://files.readme.io/b5247db-Screen_Shot_2024-03-25_at_10.12.48_AM.png) ![](https://files.readme.io/9051661-Screen_Shot_2024-03-25_at_10.10.41_AM.png)

Under **Wait time settings** , you can shorten the wait nodes to speed up the test process. Select **Set all wait times (time delay nodes, time-out settings) to** and set a new wait time. The wait time will be applied to the following nodes.

  * Time delay nodes
  * Wait for conditions nodes: Time-out settings
  * Message nodes: Time-out settings

![](https://files.readme.io/5645ba8-Screen_Shot_2024-03-25_at_10.15.25_AM.png)

Under **Trigger node settings** , if you select **Bypass the trigger node** , the test user will automatically enter the journey even if they do not meet the trigger condition.

![](https://files.readme.io/2156b61-Screen_Shot_2024-03-25_at_10.15.25_AM_copy.png)

Finally, click **Start test journey** to begin testing. In test mode, you can see the test user's position in the journey.

![](https://files.readme.io/a803e0a-Test_user_journey.png)

> 📘
> 
> ### 
> 
> Note
> 
> You may be subject to messaging fees when you send email and SMS messages during the test.

## 

Publish the journey

When you have completed the settings, click **Publish**.

![](https://files.readme.io/a38267e-Screen_Shot_2023-12-05_at_12.20.19_PM.png)

Once the journey starts running, its status will change to **Active**.

![](https://files.readme.io/20ad438-Screen_Shot_2023-12-05_at_12.14.33_PM.png)

### 

Editing the journey after publishing

To make edits after publishing, you need to pause the journey first. To pause a journey, click the three dots next to the journey's name, then click **Pause journey map**.

![](https://files.readme.io/85c3f99-pause-journey.png)

Please note that making certain types of edits on a journey after publishing it may affect performance data.

  * Changing the journey structure (e.g. moving a node to another position) will clear the performance data of each affected node.
  * Modifying a creative in a message node has no effect on that node's performance data.

# Wait Node

To add a wait node, click the circle in between nodes and select Time delay.

![](https://files.readme.io/10d64401c14f3d59cd27e65127b45ec4dbab82bc65897b511854f20e66ae2db5-wait-node.png)

* * *

## 

Time delay

You can keep the users at the current node for a period of time or until a time slot.

![](https://files.readme.io/65d937a-wait_time_delay.png)

  * **Wait for a period of time** : Users are moved to the next node in the journey map after a certain period of time has passed. You can set a duration under **How long should people wait for**.
  * **Wait until a time slot** : Users are moved to the next node in the journey map when they reach a specified timeslot during the day or during the week.
    * Select **Daily** if you want to set timeslots during certain hours of the day.
    * Select **Weekly** if you want to set timeslots during certain days of the week.
