Email provider note

Inbox access in this app is implemented for Gmail via the local gog CLI and your OAuth setup. Support for other providers (Outlook, etc.) is not included—teams that need them should build their own ingestion pipeline or replace the Gmail tool layer.

Sova — CSM Radar Agent 24/7

Built for CSM teams: monitor inbound client asks, surface only actionable tasks, and keep work transparent across status and run history.

Quick start
1) Configure agent profile
Set vendor, role, and product scope in Workbench so triage is context-aware.
2) Scan inbox
Run probe from Workbench to generate structured action cards in the dashboard.
3) Triage by status
Use Not started / In progress / Completed to manage execution and sorting.
4) Discuss one action deeply
Use "Discuss this action" to open a scoped thread and fetch the exact email thread when needed.
5) Schedule inbox probes
Use the Cron tab for presets and schedules, or describe cadence in Workbench (cron admin mode) when your message is about jobs.
Feedback & self-evolution

Open Run history, expand a run, and tap Correct, Incorrect, Useful, or Noisy. Feedback is saved into learning memory and distilled into reusable rules for future runs.

Product docs & RC URLs

Go to the Knowledge tab. Under Upload, add .md, .txt, .pdf, or .docx (product or internal docs), then click Reindex so search can surface them. Under RC URLs, add docs or portal base URLs and enable those domains so the agent may use web search during runs.

Configure

Choose provider preset, models, API keys, and Gmail gog fields. Save configuration stores values in this app’s database. Clear all database overrides removes everything saved from this screen, deletes local gog OAuth tokens under GOG_HOME (see Gmail section), and restores built-in defaults.

After changing embedding model, run Reindex on the Knowledge tab.

Provider & APIOpenRouter / OpenAI / Gemini (OR)

Choose a preset, then Apply defaults or edit fields. Chat uses an OpenAI-compatible HTTP client.

Paste your OpenRouter API key here and Save configuration to store it in the app database on this machine.

Use a valid IANA zone (e.g. Asia/Seoul). Thread list, message times, action cards, run traces, and cron summaries all display in this timezone. LangSmith emits traces for new runs only when tracing is on and a key is set.

LLM models

Gray lines show recommended defaults (starting point only). Pick a suggestion or paste any OpenRouter model id.

Retrieval ranking policy

Vendor-agnostic retrieval policy for LLM reranking. This controls ranking behavior (not hardcoded boosts).

Embeddings (RAG)

CSM guardrails

Include/exclude intents use one natural-language rule per line (or a JSON array). Matching prefers embeddings (same stack as RAG) when API keys are set; otherwise phrase/word overlap. Delete a line to remove a rule.

Agent prompts · runtime surfaces

Overview, what you can edit here, and the four database-backed templates in one place. See Effective prompts by mode below for assembled previews.

Source of truth: the four templates live in the app database (app_settings). Bundled defaults in src/agent/prompts.py only fill or repair empty rows.

On server start or when you open Configure, missing or blank prompt rows are back-filled from bundled defaults and saved. Clearing a field (whitespace only) and saving resets that row to the bundled default.

Curly braces {…} are runtime placeholders — keep {vendor_name}, {product_context}, {role_title}, and {learning_section}. Profile fills the first three; {learning_section} comes from distilled learning (Run history feedback), not the profile form.

Used by: main LangChain agent — Workbench chat when probe=false, and shared base for other modes.

Used by: inbox probe — human-style turn for inbox_probe mode (see Effective prompts by mode).

Used by: inbox_probe — appended to the system prompt when the agent runs with probe=true (Scan inbox / cron).

Used by: action_review — “Discuss this action” threads scoped to one dashboard card.

Distilled learning rules

Read-only text injected into the main template as {learning_section} (from Run history feedback). Separate from interaction compaction (agent_memory).

RC URLs (web sources)

        

          URL-tree discovery lists same-domain doc URLs (with optional titles). For each query, an LLM picks the best-matching URLs (up to your visit limit), we fetch those pages and synthesize. If evidence is still weak, we return a clear no-evidence message and do not fall back to provider web search for that host.
