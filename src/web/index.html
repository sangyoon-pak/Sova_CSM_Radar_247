Email provider note

Inbox access in this app is implemented for Gmail via the local gog CLI and your OAuth setup. Support for other providers (Outlook, etc.) is not included—teams that need them should build their own ingestion pipeline or replace the Gmail tool layer.

Quick start
1) Configure agent profile
Set vendor, role, and product scope in Workbench so triage is context-aware.
2) Scan inbox

3) Triage by status
Use Not started / In progress / Completed to manage execution and sorting.

Feedback & self-evolution

Open Run history, expand a run, and tap Correct, Incorrect, Useful, or Noisy. Feedback is saved into learning memory and distilled into reusable rules for future runs.

Product docs & RC URLs

Go to the Knowledge tab. Under Upload, add .md / .txt product or internal documents, then click Reindex so search can surface them. Under RC URLs, add docs or portal base URLs and enable those domains so the agent may use web search during runs.

Agent prompts (database)

These strings are stored in the app database and are what the agent uses at runtime. On first start, defaults are copied from src/agent/prompts.py. Clear a field and Save configuration to reset that row to the built-in default (still saved in the database).

Curly braces {…} are runtime placeholders—do not paste your vendor name or product list in place of them. Keep {vendor_name}, {product_context}, {role_title}, and {learning_section} exactly as written. At run time, the first three are filled from Workbench → Agent profile (vendor, product scope, role title). {learning_section} is filled from learning memory (distilled from Run history feedback), not from the profile form. Everything else in the template is yours to edit—rules, tone, and instructions—without changing those four placeholder names.
